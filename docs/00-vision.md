# 00. 제품 비전

## 문제 정의

한국의 부동산·금융 세제는 다음 특성 때문에 개인이 스스로 관리하기 어렵다.

1. **핀셋 규제**: 취득 시점, 계약 시점, 잔금일, 조정대상지역 지정/해제 시점, 보유 주택 수, 보유 기간, 거주 기간 등 수많은 축이 교차하며 적용 규칙이 달라진다. 같은 아파트라도 "2020년 7월 10일 이전 계약 여부" 하나로 세율이 수 배 차이 난다.
2. **빈번한 개정**: 매년 세법개정안 + 수시 시행령 개정 + 한시적 유예 조치(예: 다주택자 양도세 중과 한시 배제)가 겹쳐, 어느 시점에 어떤 규칙이 유효한지 추적이 어렵다.
3. **경과규정(grandfathering)**: 개정 시 기존 보유자에게는 종전 규정을 적용하는 경과규정이 붙는 경우가 많아, "현재 규칙"만 알아서는 내 세금을 계산할 수 없다. **내 자산의 이력**과 **규칙의 이력**을 함께 알아야 한다.

## 해결 방식

> **자산 이력(시계열 이벤트) × 세법 규칙(시행일 버전 관리) = 세액 계산 + 변화량 + 절세 시나리오**

- 사용자는 자산에 일어난 **사실**만 기록한다: 매매 계약 체결, 잔금 지급, 등기, 전입, 임대차 계약, 주식 매수/매도, 계좌 개설 등.
- 앱은 시행일별로 버전 관리되는 **규칙 데이터**를 내려받아, 사용자의 이벤트 타임라인에 대해 각 세목의 세액을 계산한다.
- 규칙 데이터가 갱신되면(세법 개정) 개정 전/후 세액을 **diff**로 보여준다: "이번 개정으로 당신의 예상 양도세가 1,200만 원 줄었습니다."
- "지금 팔면 vs 2년 더 보유하면", "A를 먼저 팔면 vs B를 먼저 팔면" 같은 **가상 이벤트 시나리오**를 시뮬레이션한다.

## 대상 사용자

| 페르소나 | 상황 | 핵심 니즈 |
|---|---|---|
| 1주택 + 국내외 주식 투자자 (초기 핵심) | 본인. 부동산 1~2건, ISA/일반계좌/연금계좌에 다수 티커 보유 | 양도세 비과세 요건 충족 여부, ISA 만기 전략, 해외주식 양도세 250만 공제 활용 |
| 일시적 2주택 / 갈아타기 | 신규 주택 계약 후 종전 주택 처분 기한 관리 | 처분 기한 D-day, 기한별 세액 차이 |
| 다주택 + 임대사업 | 임대차 계약 다수, 임대소득 종합/분리과세 | 보유세 예측, 매도 순서 최적화 |

## 성공 기준

1. 사용자가 자산 이력을 입력하는 데 자산 1건당 5분 이내.
2. 계산 결과마다 "왜 이 금액인가"를 조문·규칙 단위로 설명(explain) 가능.
3. 세법 개정 규칙 데이터 반영이 앱 코드 배포 없이 가능 (규칙 파일 갱신만으로).
4. 개인 자산 데이터가 사용자 기기 밖으로 나가지 않음 (1차 버전).

## 비목표 (Non-Goals)

- **세무 신고 대행/연동 아님**: 홈택스 신고서 생성, 자동 신고는 범위 밖. 참고용 계산기 + 내비게이터다.
- **모든 세목 커버 아님**: 상속·증여세, 법인세, 사업소득 일반은 초기 범위 밖 (증여는 시나리오 항목으로만 후순위 검토).
- **실시간 시세 정확성 보장 아님**: 공시가격·시세는 사용자 입력 또는 참고 API이며 추정치임을 명시.
- **법적 자문 아님**: 모든 화면에 면책 고지. 큰 의사결정 전 세무사 상담 유도.

## 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 규칙 데이터의 오류·누락 → 잘못된 의사결정 유도 | 규칙마다 근거 조문·시행일·출처 명시, 신뢰도 등급 표기, 테스트 케이스(공식 사례 기반) 필수화, 면책 고지 |
| 세법의 판정 불확실성 (예: '1세대' 판정, 실거주 인정) | 판정 근거를 사용자에게 보여주고, 불확실 요소는 "가정"으로 명시하여 사용자가 토글 가능하게 |
| 규칙 유지보수 부담 | 규칙을 코드가 아닌 선언적 데이터로 설계해 기여 장벽을 낮춤. 개정 시 변경분만 새 버전 규칙으로 추가 |
| GitHub Pages 정적 환경의 한계 | 계산 전부 클라이언트에서 수행 가능하도록 규칙 엔진을 순수 함수로 설계 |
