# 06. 개발 로드맵

원칙: **엔진과 데이터 모델을 먼저 검증하고 UI는 나중에 입힌다.** 가장 큰 리스크는 UI가 아니라 (a) 규칙을 데이터로 표현할 수 있는가, (b) 이벤트 재생으로 판정 facts를 정확히 뽑을 수 있는가이다. 이 둘을 Phase 0에서 소규모로 증명한다.

## Phase 0 — 검증 스파이크 (2~3주)

**목표: 아키텍처 가설 증명. UI 없음, 테스트만.**

- [ ] 모노레포 스캐폴딩 (pnpm workspaces: engine / rules / web 빈 껍데기)
- [ ] 이벤트·자산 TypeScript 타입 + Zod 스키마 (docs/02 기준)
- [ ] replay 엔진: 이벤트 로그 → facts (주택 수, 보유·거주기간, 평단가, 실현손익)
- [ ] Rule JSON Schema + 조건식 인터프리터 (화이트리스트 연산자)
- [ ] **수직 슬라이스 2개를 끝까지**:
  1. 해외주식 양도세: 매수/매도 이벤트 → 연간 실현손익 → 250만 공제 → 세액 (환율 포함)
  2. 1세대 1주택 양도세 비과세 판정: 취득·전입 이벤트 → 보유/거주기간 → 비과세/과세 + 고가주택 초과분
- [ ] 국세청 공식 계산 사례 ≥ 5건을 테스트로 통과
- [ ] **경과규정 1건을 규칙 데이터로 표현해보기** (예: 취득세 중과의 계약일 경과규정) — 표현 불가하면 스키마 재설계
- [ ] **원문 수집 스파이크** ([[07-law-ingestion]]): law.go.kr Open API 키 발급, 소득세법 시행령 XML 수집 + 조문 트리 파싱, 슬라이스 규칙 2건의 source 필드(원문 해시·조문 경로)를 실제 보관본으로 채우기

**Phase 0 판정 기준**: 위 두 슬라이스가 규칙 JSON 수정만으로 (코드 수정 없이) 세율 변경에 대응되면 통과.

## Phase 1 — MVP: 해외주식 + 단일 주택 (4~6주)

**목표: 본인이 매일 쓰는 도구. GitHub Pages 첫 배포.**

범위 (P0 기능만):
- 입력 위저드: 부동산 1건(계약~잔금~전입), 계좌+티커 매수/매도
- 대시보드: "지금 팔면" 양도세, 비과세 요건 진행바, 해외주식 공제 잔여
- explanation trace 뷰 ("왜 이 금액인가")
- 시나리오 1개: 가상 매도 이벤트 + 비교
- 데이터 내보내기/가져오기 (암호화)
- D-day 목록
- CI: 규칙 테스트 + Pages 자동 배포

규칙 데이터 범위: 해외주식 양도세, 국내주식 대주주 파라미터, 1주택 양도세(비과세·장특공제·기본세율), 조정대상지역 이력 테이블.

원문 파이프라인: 소관 법령 전체의 WATCH+FETCH+ARCHIVE 자동화 (일 1회 cron), 조문 단위 diff + 원문 diff 첨부 PR 자동 생성 (규칙 초안 작성은 수동).

## Phase 2 — 부동산 심화 + 개정 대응 (6~8주)

- 다주택 판정 (일시적 2주택, 분양권/입주권 포함 규칙)
- 취득세 (중과 + 계약일 경과규정)
- 보유세 (재산세 + 종부세, 공시가 입력)
- **RuleSet diff → 개정 영향 리포트** (F3-1, 차별화 핵심)
- 시간축 스윕 차트 (F4-3), 매도 순서 비교 (F4-4)
- CSV 거래내역 가져오기
- 임대차 계약 + 임대소득 (분리/종합 비교)
- 원문 파이프라인: 조문→규칙 매핑표(diff 시 영향 규칙 자동 산출), 파라미터형 규칙 자동 초안, 부칙 변경 경고 라벨, 조정대상지역 고시 수집

## Phase 3 — 절세 계좌 + 고도화 (6주+)

- ISA 만기 시나리오, 연금계좌 세액공제 추적
- 배당·금융소득종합과세 누계
- scheduled RuleSet (개정안 가상 적용) — 국회 의안 API 연동으로 계류 개정안 추적
- 원문 파이프라인: LLM 보조 초안(요건/판정형 규칙), 국세청 사례집 → 테스트 케이스 반자동화
- 손익통산 제안, .ics 내보내기
- 사용자 피드백 기반 규칙 커버리지 확장

## Phase 4 — 앱 런칭

- Capacitor vs React Native 결정 (웹 사용 데이터·피드백 기반)
- SQLite 스토리지 어댑터 (엔진 무변경)
- 로컬 푸시 알림 (D-day), 생체인증 잠금
- 웹 → 앱 데이터 이관 흐름 (백업 파일 가져오기)
- (선택) E2E 암호화 클라우드 동기화

## 지속 운영 트랙 (모든 Phase 병행)

- **규칙 데이터 유지보수**: 원문 수집 파이프라인이 개정을 감지해 PR을 올리면 → 사람이 원문 대조 검증 → 테스트 → 배포. 개정 시즌(7~8월 세법개정안, 12~1월 국회 통과, 2월 시행령) 집중 — 시즌 캘린더는 [[07-law-ingestion]] 참조.
- **수집기 헬스체크**: 크롤러/API 실패 시 자동 Issue 생성, "마지막 성공 수집일" 대시보드 노출.
- 규칙 confidence 갱신 (checkedAt 오래된 규칙 재검증)
- 회귀 시나리오 스위트 확장 (실사용 케이스 익명화 편입은 프라이버시 원칙상 수동 작성만)

## 첫 실행 항목 (다음 세션에서 시작할 일)

1. Phase 0 스캐폴딩 + 이벤트 타입 정의
2. 해외주식 수직 슬라이스 (가장 단순, 규칙 수 적음 → 엔진 검증에 최적)
3. 1주택 비과세 슬라이스 (시간 파생·경과규정 검증)
